# M1: Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People can join through an invite, sign in with a username + password or Google, finish a
short onboarding, manage their profile, password, sign-in methods and account, and admins can create
invites and password-reset links.

**Architecture:** Better Auth owns sessions, password hashing, Google OAuth and account linking, and
is constructed by a pure factory (`createAuth`) so services and tests can build it against any `Db`.
Our own services (`src/lib/server/auth/*`) own every product rule Better Auth doesn't know: invites,
password policy, per-username throttling, admin reset links, onboarding and account deletion. All
user-facing auth flows are SvelteKit form actions that call these services, which call `auth.api.*`
server-side. Better Auth's public HTTP endpoints for the same operations are disabled so the form
actions are the only way in.

**Tech Stack:** Better Auth 1.7 (username plugin, Google provider, `sveltekitCookies`), Drizzle 0.45
on `pg` (node-postgres), PGlite (+ `@electric-sql/pglite-socket` for E2E), Zod 4, SvelteKit 3 form
actions, Vitest 4, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-09-habit-bingo-v2-design.md` (§4.1, §4.2, §4.10, §4.12,
§5.1, §5.3, §5.4, §7.1)

## Global Constraints

- Everything in the M0 plan's Global Constraints still applies (branch + PR per task, conventional
  commits, Prettier, `#lib/*.ts` imports with explicit `.ts`, Playful tokens, ink text on state
  colors, states never color-only, `prefers-reduced-motion` respected via `#lib/motion.ts`).
- **Usernames:** 3–20 characters, `[a-z0-9_]` after lowercasing, unique case-insensitively. Stored
  lowercased in `username`; the typed casing kept in `displayUsername`. Shown as `@{displayUsername}`.
- **Passwords:** 10–128 characters; not equal to the username (case-insensitive); rejected if found
  in Have I Been Pwned (k-anonymity range API). Hashed with Better Auth's default scrypt.
- **Display name:** Better Auth's `name` field; trimmed, 1–40 characters.
- **Sign-up only through a valid invite:** not expired, `uses < maxUses`. Both methods.
- **Google sign-in scopes:** Better Auth defaults only (`openid email profile`). Never calendar.
- **Linking Google:** only from a signed-in session (`linkSocial`), never implicitly by email.
  A user must always keep at least one sign-in method.
- **Reset links:** 32 random bytes, base64url in the URL, SHA-256 hex stored, single use, expire
  after 24 hours. Using one, or changing a password, revokes every other session.
- **Sign-in errors never reveal whether a username exists.** Exact copy: `Wrong username or password.`
- **Lockout:** 5 failed sign-ins for a username within 15 minutes locks that username for
  15 minutes, whether or not it exists. Copy: `Too many attempts. Try again in a few minutes.`
- **Placeholder email** for password-only users: `` `${crypto.randomUUID()}@users.invalid` ``. Never
  displayed, never emailed.
- **Cookie names** are prefixed `hb` (Better Auth `advanced.cookiePrefix: 'hb'`). The invite cookie
  is `hb_invite`: `httpOnly`, `secure`, `sameSite: 'lax'`, `path: '/'`, `maxAge: 3600`.
- **npm override** (required for every install): Better Auth's optional peer range stops at
  `@sveltejs/kit` 2, so `package.json` carries
  `"overrides": { "better-auth": { "@sveltejs/kit": "$@sveltejs/kit" } }`. Verified to install and
  run on Kit 3 (spike, 2026-10-09).
- New env vars, all declared in `src/env.ts`: `BETTER_AUTH_SECRET` (required at runtime, ≥ 32
  chars), `BETTER_AUTH_URL` (optional), `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (optional; Google
  is hidden when unset), `BOOTSTRAP_INVITE_CODE` (optional). `npm run build` must still succeed with
  none of them set.

**Deliberate deviations from the spec** (update the spec and ADRs in the task named):

1. **Database driver** `@neondatabase/serverless` → `pg` (node-postgres) over TCP to Neon's pooled
   endpoint (Task 1, ADR 0002). Neon's WebSocket driver cannot reach a local Postgres, so E2E tests
   could not have a real database. `pg` works on Vercel's Node runtime and against PGlite's socket
   server.
2. **No test-only sign-in route** (spec §7.1). E2E data is seeded straight into the E2E database
   before the server starts (Task 4). Nothing test-only ships in the production build.
3. **Google sign-in only works on production** (and `localhost`): Google requires exact redirect
   URIs and preview URLs are random. Previews exercise the password path. Recorded in Task 10.

## Review Focus

1. **CSP blocks the Google redirect.** `form-action 'self'` also restricts where a form submission
   may redirect; the Google button posts to our action, which 303s to `accounts.google.com`. Expect
   Google sign-in to work. Pinned in Task 7.
2. **A failed sign-up burns an invite.** If the username is taken or the password is rejected, the
   person retries; the invite must still have its use. Pinned in Task 4.
3. **Dead invite links.** Expired, used-up or mistyped codes must show a friendly page, never a 500,
   and must not set the invite cookie. Pinned in Task 4.
4. **Signing out really ends the session.** A copied session cookie must stop working after sign
   out and after "Sign out everywhere". Pinned in Task 5 and Task 8.
5. **Lockout as a username oracle.** A non-existent username must get the same error, the same
   timing class and the same lockout as a real one. Pinned in Task 5.

### Task 3: Password policy, breach check and invites

**Branch:** `feat/password-policy-invites`

**Files:**

- Create: `src/lib/server/auth/pwned.ts`, `pwned.spec.ts`, `password-policy.ts`,
  `password-policy.spec.ts`, `invites.ts`, `invites.spec.ts`
- Modify: `src/lib/server/auth/create-auth.ts` (hooks), `create-auth.spec.ts`

**Interfaces:**

- Produces:
  - `isPwnedPassword(password: string, fetchFn?: typeof fetch): Promise<boolean>`: SHA-1 (upper
    hex) → GET `https://api.pwnedpasswords.com/range/{first5}` with header `Add-Padding: true`;
    true if a returned line's suffix matches with count > 0. **Fails open**: network error or
    non-200 → `false`, logged as `{ level: 'warn', source: 'hibp' }`.
  - `type PasswordProblem = 'tooShort' | 'tooLong' | 'sameAsUsername' | 'breached'`
  - `checkPassword(password: string, username: string | null, isPwned: (p: string) => Promise<boolean>): Promise<PasswordProblem | null>`
  - `PASSWORD_MESSAGES: Record<PasswordProblem, string>`: `tooShort` "Use at least 10 characters.",
    `tooLong` "Use at most 128 characters.", `sameAsUsername` "Your password can't be your
    username.", `breached` "This password has appeared in a data breach. Choose a different one."
  - `type InviteStatus = 'valid' | 'expired' | 'usedUp' | 'notFound'`
  - `createInvite(db: Db, input: { createdBy: string; expiresInDays: number; maxUses: number; groupId?: string }, now: Date): Promise<{ code: string }>`:
    code = 10 random bytes as base64url.
  - `getInviteStatus(db: Db, code: string, now: Date): Promise<InviteStatus>`
  - `consumeInvite(db: Db, code: string, now: Date): Promise<boolean>`: one atomic
    `UPDATE invite SET uses = uses + 1 WHERE code = $1 AND uses < max_uses AND expires_at > $now RETURNING code`.
  - `createAuth` gains: `hooks.before` middleware that runs `checkPassword` for `/sign-up/email`
    (`ctx.body.password`, `ctx.body.username`), `/change-password` (`newPassword`, session user's
    username) and `/set-password`, throwing `APIError('BAD_REQUEST', { message: PASSWORD_MESSAGES[problem], code: problem })`;
    and `databaseHooks.user.create.before` that reads the invite code from the request's `hb_invite`
    cookie and calls `consumeInvite`; if it returns false, throws
    `APIError('FORBIDDEN', { code: 'INVITE_REQUIRED', message: 'You need an invite to join.' })`.
    **Bootstrap:** when `options.bootstrapInviteCode` equals the cookie value and there are zero
    users, creation is allowed and the user is returned with `isAdmin: true`.
