# M8 Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Friends can create groups, invite each other with a standing link, see a This month / All-time leaderboard and view each other's cards, with private habits hidden.

**Architecture:** Two tables (`group`, `group_member`); a group's link is an `invite` row with its `groupId`. All membership rules and visibility checks live in `src/lib/server/groups.ts`; the leaderboard and member card are read models in `src/lib/server/leaderboard.ts` built on the existing `cardView` and M7's `finalizeMonths`; ranking is a pure function in `src/lib/game/leaderboard.ts`. Sign-up through a group link reuses the account-creation hooks in `create-auth.ts`.

**Tech Stack:** SvelteKit 3 / Svelte 5 runes, Drizzle on Postgres (PGlite in tests), Vitest 4, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-09-habit-bingo-v2-design.md`, §3.8 (lazy finalization), §3.9 (leaderboards), §4.9 (groups), §5 (`group`, `group_member`, `invite`).

## Global Constraints

- TDD: every test is run and seen failing before its code. `src/lib/game/**` keeps 100% branch coverage.
- Imports use `#lib/*.ts`; hrefs use `resolve()` inline (scoped `eslint-disable svelte/no-navigation-without-resolve -- reason` only where a query string is needed).
- Every action works without JavaScript (plain form posts and 303 redirects); enhanced forms keep scroll (`invalidateAll` on redirect, as Today does).
- Anyone outside a group gets **404** (`error(404, 'Not found')`) for its pages, its members' cards and its actions — never 403.
- Group name 1–40 characters after trimming; group emoji passes the existing `isSingleEmoji`. Members cap: **50**.
- Exact copy: "No groups yet. Create one, or ask a friend for their invite link." · "This invite link no longer works." · "Join {group}" · "No card yet" · "No {Month} card yet." · "Owner" · "Includes {Month}, which is final on the 4th." · 🔒 replaces a private habit's name and emoji.
- "Today" for a person is always their local date: `localDate(requestNow(cookies, TEST_CLOCK), timezone ?? 'UTC')`; for other members use **their** `user.timezone`.
- Spec decisions already made: no scheduled job, no group rank in the recap, no renaming groups, no manual ownership transfer, no Feed tab.

## Review Focus

1. Two people take the 50th spot at the same moment: exactly 50 members, the other gets a "full" refusal. → Task 3 test.
2. The owner leaves while two members joined at the same instant: ownership goes to a deterministic one (earliest `joinedAt`, then lowest `userId`), never to nobody. → Task 3 test.
3. A person removed from a group (or who left) reloads its page or posts one of its actions: 404, not a stale view. → Task 3 test (`getMembership` returns null after removal) and Task 7 route uses it on every load and action.
4. A member card for someone who shares a _different_ group with the viewer, opened through this group's URL: 404. → Task 4 test.
5. A link reset while someone still has the old one open, who then signs up or presses Join: refused with "This invite link no longer works.", no membership, no account consumed for a dead group link. → Task 3 and Task 5 tests.

### Task 3: Membership rules

**Files:**

- Create: `src/lib/server/groups.ts`, `src/lib/server/groups.spec.ts`

**Interfaces:**

- Consumes: Task 1 tables; `createInvite`, `getInviteStatus` (`auth/invites.ts`); `isSingleEmoji`.
- Produces (all scoped to the acting person):
  - `MAX_MEMBERS = 50`, `DEAD_LINK_MESSAGE = 'This invite link no longer works.'`, `FULL_MESSAGE = 'This group is full.'`
  - `createGroup(db, userId, input: { name: string; emoji: string }, now: Date): Promise<{ ok: true; groupId: string } | { ok: false; field: 'name' | 'emoji'; message: string }>` — owner membership + a standing invite (`expiresInDays: 36500`, `maxUses: 1_000_000`) in one transaction.
  - `listGroups(db, userId): Promise<{ id; name; emoji; memberCount: number }[]>` — the person's groups, by name.
  - `getMembership(db, userId, groupId): Promise<{ group: { id; name; emoji }; role: 'owner' | 'member'; inviteCode: string } | null>` — null when not a member (every group route starts here).
  - `listMembers(db, groupId): Promise<{ userId; displayUsername; avatarEmoji; timezone; role; joinedAt }[]>` — by `joinedAt`.
  - `groupForInvite(db, code, now): Promise<{ group: { id; name; emoji }; memberCount: number } | 'dead' | null>` — null for a non-group invite; `'dead'` when the invite is a group invite that is not valid or its group is gone.
  - `joinGroup(db, userId, code, now): Promise<{ ok: true; groupId: string } | { ok: false; message: string }>` — idempotent for an existing member; dead link → `DEAD_LINK_MESSAGE`; full → `FULL_MESSAGE`. Count-and-insert under `pg_advisory_xact_lock(hashtext('group:' || groupId))`, like `startCard`.
  - `leaveGroup(db, userId, groupId): Promise<'left' | 'deleted' | null>` — owner leaving promotes the earliest `joinedAt` (then lowest `userId`); the last member leaving deletes the group and expires its invites (`expiresAt = now`). Same lock.
  - `removeMember(db, ownerId, groupId, memberId): Promise<boolean>` — false unless the actor is the owner and the target is another member.
  - `resetInvite(db, ownerId, groupId, now): Promise<string | null>` — owner only: expires the group's live invites and creates a new standing one; returns the new code.

- [ ] **Step 1: Write the failing tests** (helpers as in `month-results.spec.ts`):
  - create: owner role, one live invite, name trimmed; empty name, 41 characters, and `'ab'` emoji refused with their field.
  - join: by code adds a member; joining twice → still one row, `ok: true`; a reset (expired) code → `{ ok: false, message: DEAD_LINK_MESSAGE }`; an admin (no `groupId`) invite → refused.
  - cap: with 49 members, `Promise.all` of two joins → exactly 50 members, one `FULL_MESSAGE` (Review Focus 1).
  - leave: member leaves → gone; owner leaves → earliest-joined becomes owner; two members with the same `joinedAt` → lower `userId` becomes owner (Review Focus 2); last member leaves → group row gone, its invite reads `'dead'` through `groupForInvite`.
  - remove: owner removes a member → their `getMembership` is null (Review Focus 3); a member cannot remove; the owner cannot remove themselves.
  - reset: non-owner → null; owner → new code joins, old code → `DEAD_LINK_MESSAGE` (Review Focus 5).
  - `getMembership` for a stranger → null.
- [ ] **Step 2: Run** `npx vitest run --project server src/lib/server/groups.spec.ts` — Expected: FAIL.
- [ ] **Step 3: Implement** `groups.ts`.
- [ ] **Step 4: Run** the spec — Expected: PASS.
- [ ] **Step 5: Commit** `feat(groups): membership rules`

### Task 4: Leaderboard and member card

**Files:**

- Create: `src/lib/server/leaderboard.ts`, `src/lib/server/leaderboard.spec.ts`

**Interfaces:**

- Consumes: `getMembership`, `listMembers` (Task 3); `rankRows` (Task 2); `getCard`, `cardView`, `finalizeMonths`, `listResults`; `localDate`, `monthOf`, `backfillMonths`.
- Produces:
  - `type BoardRow = { userId; displayUsername; avatarEmoji; points: number | null; lines: number | null; rank: number | null; isViewer: boolean }`
  - `groupBoard(db, viewerId, groupId, board: 'month' | 'all', now: Date): Promise<{ rows: BoardRow[]; provisionalMonth: string | null } | null>` — null when the viewer is not a member. `month`: each member's card for the month of _their_ local date, `cardView` score at that date; no card → `points: null`. `all`: first `finalizeMonths(db, member.id, memberToday)` per member, then sum of `listResults` points plus this month's live points (no card → 0; every member ranked). `provisionalMonth`: the viewer's previous month (`YYYY-MM`) when it is still in the viewer's backfill window and part of a total, else null.
  - `memberCard(db, viewerId, groupId, memberId, now: Date): Promise<{ member: { displayUsername; avatarEmoji }; monthName: string; card: { size; squares: ViewSquare[]; score: CardScore } | null } | null>` — null unless both are members of **this** group. Squares carry no `id`/`link`; a private habit's `name` and `emoji` both become `'🔒'`; rewards are not returned.

- [ ] **Step 1: Write the failing tests:**
  - month board: two members with cards and logs rank by points; a member without a card is last with `points: null`; the viewer's row has `isViewer: true`; a stranger → null.
  - timezone: a member in Pacific/Kiritimati at `2026-10-31T11:30Z` is scored on their November card (none → `points: null`), the UTC member on October.
  - all-time: a member who never opened the app gets their finished October finalized by viewing (row in `month_result`), and their total = October result + November live; `provisionalMonth` is `'2026-10'` on Nov 2 and null on Nov 4.
  - member card: shows the member's current card; a private habit square reads `🔒` for name and emoji; no `rewards` key; a member of another group shared with the viewer but not this one → null (Review Focus 4); a member with no card → `card: null`.
- [ ] **Step 2: Run** `npx vitest run --project server src/lib/server/leaderboard.spec.ts` — Expected: FAIL.
- [ ] **Step 3: Implement** `leaderboard.ts` (one `listMembers` call, then per-member queries in `Promise.all`).
