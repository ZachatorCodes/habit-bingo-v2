# M9 Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each group gets a Feed of members' highlights with one-per-person icon reactions. Highlights are posted when a check-in makes them true and removed when it makes them false.

**Architecture:**

- **Schema:** two tables (`feed_event`, `reaction`) in migration `0012`.
- **Pure diff:** `highlightChanges(before, after)` in `src/lib/game/feed.ts` decides what to post and remove.
- **Server module:** `src/lib/server/feed.ts` writes inside the check-in and card transactions, and reads and reacts for the group page.
- **UI:** the group page gains a default Feed tab (phone and iPad portrait), and Feed becomes the main column at ≥1024px.

**Tech Stack:** Drizzle + Postgres (PGlite in tests), SvelteKit 2 form actions, Svelte 5, Tailwind v4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-23-m9-feed-design.md` (the authority; v2 spec §4.9 is background).

## Global Constraints

- **Highlights exist only while true.**
  - "At least" squares post on becoming `complete`; "at most" squares never post.
  - Tiers post only on a not-reached → reached transition caused by a check-in.
  - Starting a card posts only `cardStarted`.
  - Removal deletes the event, and its reactions cascade.
- **Event key:** `(card_id, key)` is unique, with `key` ∈ `card` | `square:<squareId>` | `tier:bingo` | `tier:sixtyPercent` | `tier:blackout`. Inserts use `ON CONFLICT DO NOTHING`.
- **Private habits** are never named: the payload is `{ private: true }`.
- **Reactions:** exactly six icons, `heart`, `fire`, `hands-clapping`, `trophy`, `star`, `smiley`. One reaction per (event, user); the same icon again toggles it off.
- **Visibility:** only group members read a group's feed. Reacting requires sharing a group with the event's author. Everything else returns 404.
- **Migrations:** generate them with `npm run db:generate` (drizzle-kit, which reads the schema only). **Never** run `db:migrate`, `db:studio` or `npm run dev`, and never read `.env`. Tests apply migrations to PGlite.
- **UI:** Garden tokens, `Icon`, ≥44px targets, and text ≥12px. Hover only in `@media (hover: hover)`. Reactions work without JavaScript. The phone UI otherwise stays unchanged, apart from the new Feed tab and the default.
- **Coverage:** `src/lib/game` keeps 100% coverage.
- **Before committing:** `npm run check`, plus `npx prettier --check` and `npx eslint` on the touched files.

## Review Focus

1. **Concurrent check-ins:** two simultaneous logs on squares that together complete a line must post exactly one bingo, and never post-then-delete it. Test: Task 2, "simultaneous logs post one bingo" (`Promise.all` of two `logCheckIn` calls).
2. **A tier already held at card start, then lost and regained by check-ins:** it must post on the regain, because that's a real transition, and must not post on the first unrelated check-in. Test: Task 1, `highlightChanges` cases.
3. **A habit swapped during the edit window:** its old square event must not remain under the new habit's name. Test: Task 2, "swapping a habit removes its square event".
4. **A member who leaves a group:** their events drop out of that group's feed, and their existing reactions stay on other members' items. Test: Task 1, a `groupFeed` case.
5. **The react form posted with an unknown icon or a foreign event id:** it fails with 400 or 404, never 500. Test: Task 3 e2e, "bad react posts are refused".

### Task 1: Schema, pure diff and the feed service

**Files:**

- Create: `src/lib/server/db/schema/feed.ts` (exported from `schema.ts`), `src/lib/game/feed.ts`, `src/lib/game/feed.spec.ts`, `src/lib/server/feed.ts`, `src/lib/server/feed.spec.ts`, and the `drizzle/0012_*.sql` migration (generated)
- Modify: `src/lib/icons.ts` and `src/lib/components/Icon.svelte` to add `fire` (Phosphor `Fire`) and `hands-clapping` (`HandsClapping`) if missing, all six in `RESERVED`, unless already pickable habit icons (then leave them pickable)

**Interfaces:**

- Produces, in `src/lib/game/feed.ts`:
  - `type HighlightState = { squares: { id: string; direction: 'atLeast' | 'atMost'; state: SquareState }[]; tiers: Tier[] }`
  - `highlightChanges(before: HighlightState, after: HighlightState): { post: string[]; remove: string[] }`, returning event keys
  - `REACTIONS = ['heart', 'fire', 'hands-clapping', 'trophy', 'star', 'smiley'] as const` and `type ReactionIcon`
- Produces, in `src/lib/server/feed.ts`:
  - `postCardStarted(tx, card: { id: string; userId: string; month: string }): Promise<void>`
  - `syncHighlights(tx, card: { id: string; userId: string }, squares: { id; name; icon; isPrivate }[], changes: ReturnType<typeof highlightChanges>): Promise<void>`
  - `groupFeed(db, viewerId: string, groupId: string, before?: string): Promise<{ items: FeedItem[]; olderCursor: string | null } | null>`, where `null` means not a member
  - `react(db, userId: string, feedEventId: string, icon: string): Promise<'added' | 'switched' | 'removed' | 'notFound' | 'badIcon'>`
  - `FeedItem = { id; type; payload; createdAt: Date; author: { userId; displayUsername; avatarIcon }; reactions: Record<ReactionIcon, number>; mine: ReactionIcon | null }`

- [ ] **Step 1: Write the failing tests.**
  - `feed.spec.ts` (game), for `highlightChanges`:
    - an "at least" square going inProgress → complete posts `square:<id>`, and complete → inProgress removes it;
    - an "at most" square never posts;
    - tiers `[]` → `['bingo']` posts `tier:bingo`, and `['bingo']` → `[]` removes it;
    - identical states give `{ post: [], remove: [] }`;
    - a tier present in both before and after posts nothing (Review Focus 2).
  - `feed.spec.ts` (server, PGlite):
    - `postCardStarted` is idempotent;
    - `syncHighlights` stores the name and icon, or `{ private: true }`, and is idempotent, and its remove deletes the reactions;
    - `react` returns added → switched → removed, `badIcon` for `'rocket'`, and `notFound` for a stranger;
    - `groupFeed` returns null for a non-member, newest first;
    - after a member leaves the group, their events are excluded (Review Focus 4);
    - with 35 events it pages 30 and then 5.
- [ ] **Step 2: Run** `npx vitest run src/lib/game/feed.spec.ts src/lib/server/feed.spec.ts`. Expected: FAIL, modules not found.
- [ ] **Step 3: Implement** the schema per spec §3 (the `key` unique constraint, the index on `(user_id, created_at desc)`, cascades, and a check constraint on `reaction.icon`). Then run `npm run db:generate`, review the SQL, and implement the two modules.

### Task 2: Post highlights from cards and check-ins

**Files:**

- Modify: `src/lib/server/check-ins.ts` (`logCheckIn`, `setCheckIn`), `src/lib/server/cards.ts` (`startCard`, `updateCard`), `src/lib/server/card-view.ts`
- Test: `src/lib/server/check-ins.spec.ts`, `src/lib/server/cards.spec.ts`

**Interfaces:**

- Consumes: from Task 1, `highlightChanges`, `syncHighlights` and `postCardStarted`.
- Produces: `highlightState(tx, cardId: string, today: string, counts?): Promise<{ state: HighlightState; squares: {...}[] }>` in `card-view.ts`. It is built from the same per-square `evaluateSquare` call and the same tier computation that `cardView` uses.

- [ ] **Step 1: Write the failing tests.**
  - Logging the check-in that completes an "at least" square creates its event, and undoing it removes the event.
  - Completing a line posts `tier:bingo` once.
  - "simultaneous logs post one bingo" (Review Focus 1).
  - "startCard posts only cardStarted": a card whose "at most" squares form a line at the start has exactly one event.
  - "swapping a habit removes its square event" (Review Focus 3).
- [ ] **Step 2: Run** `npx vitest run src/lib/server/check-ins.spec.ts src/lib/server/cards.spec.ts`. Expected: the new tests FAIL.
- [ ] **Step 3: Implement.**
  - **`logCheckIn` and `setCheckIn`:** after `checkLoggable`, run the write in `db.transaction`, beginning with `SELECT … FROM card WHERE id = $cardId FOR UPDATE`. That lock makes concurrent check-ins on one card take turns. Inside the transaction:
    1. compute `before` with `highlightState`;
    2. apply the existing write unchanged;
    3. compute `after`;
    4. call `syncHighlights(tx, card, squares, highlightChanges(before, after))`.
  - **`startCard`:** call `postCardStarted` inside its existing transaction.
  - **`updateCard`:** inside its transaction, delete `square:<id>` events for squares whose habit changed.
  - Keep return values unchanged.
- [ ] **Step 4: Run** `npx vitest run src/lib/server`, then `npx playwright test e2e/today.e2e.ts e2e/card.e2e.ts e2e/habit-sheet.e2e.ts`. Expected: all pass.
- [ ] **Step 5: Commit** `feat(feed): post highlights from check-ins and new cards`.
